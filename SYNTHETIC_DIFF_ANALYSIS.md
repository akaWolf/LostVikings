# Автономная верификация функций БЕЗ запуска игры — глубокий анализ

Запрос: цикл «переписал функцию → проверил корректность» должен работать
автономно, без запуска игры в рантайме — ни интерактивных сессий, ни записи
реплеев, ни многоминутных headless-прогонов на каждую итерацию.

Ответ: **да, можно** — изолированное дифференциальное исполнение пар функций
(orig как исполняемый оракул + v2 как проверяемый) на синтетически
сгенерированных входах. Ниже — почему это не противоречит прежним решениям,
чем отличается от отклонённых рантайм-фикстур, механическая осуществимость
(проверена по коду), дизайн, ограничения, план.

---

## 1. Три предыдущих решения и где место нового подхода

1. **Лок-степ verify (работает)** — orig и v2 сверяются побайтово в живом
   прогоне. Интеграционная истина, но: цикл = минуты, покрытие = что случилось
   в реплее, для новых сценариев нужен юзер (запись).
2. **Рантайм-фикстуры (отклонено юзером — справедливо)** — снятые с тех же
   реплеев входы/выходы дублируют сигнал лок-степ verify, пока orig-слой жив.
   Новой детектирующей способности не давали.
3. **Synthetic-тесты с ручным эталоном (отклонено мной в FN_TEST_ANALYSIS)** —
   отвергались потому, что ОЖИДАЕМЫЙ ВЫХОД пришлось бы сочинять руками =
   гадание (нарушение no-guessing).

Новый подход снимает возражения обоих отклонений:
- эталон НЕ сочиняется — эталоном служит **сам оригинал (m2c), исполняемый на
  том же входе в том же процессе**. Поведение определяет оригинал, не я;
- сигнал НЕ дублирует лок-степ verify — покрытие выходит за пределы реплеев
  (см. §2), и цикл не требует прогона игры вообще.

## 2. Почему это даёт НОВУЮ детектирующую способность (не дубль verify)

Живой пример из Phase 0: `sub_15972` имеет 3 ветки (ax<0 / ax==0 / ax>0).
За 1000 кадров attract.inp она вызвалась **2 раза, оба ax==0**. Ветки ax<0 и
ax>0 в реплее НЕ исполнялись ни разу — лок-степ verify их не проверял никогда.
Ошибка в этих ветках v2 жила бы до случайного попадания в геймплее.

Synthetic-diff покрывает: все ветки (входы строятся по asm-анализу), границы
(0, ±1, 0x7FFF/0x8000, 0xFFFF, тайловые &0xFFF0), и — поскольку параметры
16-битные — **исчерпывающий перебор ключевого параметра: все 65536 значений ax
за долю секунды**. Для функций такого класса это практически формальная
верификация ветвления.

Легитимность «нереалистичных» входов: правило проекта — v2 идентичен orig
инструкция-в-инструкцию. Две идентичные функции обязаны совпадать на **любом**
входе, достижимом или нет. Расхождение на недостижимом входе = реальная ошибка
репликации (не так переписана ветка/флаг/знак) — ровно то, что ловим. Оригинал
детерминирован на любом входе (это asm), m2c это воспроизводит — «UB на
мусоре» нет.

## 3. Механическая осуществимость — проверено по коду

1. **Каждая orig-функция вызываемая по имени**: `vikings.exe.cpp:301` —
   wrapper'ы `bool sub_XXXXX(m2c::_offsets, _STATE*){return _group1(k, st);}`.
2. **Регистры per-state, не глобальные**: `m2c::_STATE` (asm.h:148) — eax..eip,
   сегментные, флаги. Проект УЖЕ живёт с двумя state параллельно
   (`render_state`, asm.cpp:571) и уже вызывает orig-код из C++ напрямую
   (`draw_tile(_state)` seg000:244, `redraw_tilemap` seg000:127) — мультистейт
   и внешние вызовы = рабочая практика, не эксперимент.
3. **Статика EXE инициализируется ДО main**: `struct Initializer` — глобальный
   конструктор (`vikings.exe.cpp:5722`, `static const Initializer i;` :9453)
   заполняет m2c::m всеми cs-таблицами/off_-указателями/статикой DS. Любой
   бинарь, слинкованный с этими объектниками, получает корректный образ памяти
   автоматически.
4. **Среда без игры**: `m2c::init` (asm.cpp:424-451) строит только окружение —
   mcb_init кучи, стек (`ss=seg_offset(stack)`, `sp=STACK_SIZE-4`), ds/es=PSP —
   и НЕ запускает игру (её запускает отдельный `_ENTRY_POINT_`). Драйверу
   нужен этот же троестрочный сетап (без render/sound init).
5. **Выход из группы после RETN** — единственный недостающий механизм.
   `CALL_` пушит ret-eip в эмулированный стек; `RETN_` попает и уходит в
   `__dispatch_call` (switch по eip). При вызове функции извне на дне стека
   нет валидного ret-eip. Решение (2 строки в seg000, паттерн хуков Phase 0):
   trap-метка внутри группы + case в диспетчер-switch:
   ```
   fntest_ret_trap: return true;               // выход из _group1 → wrapper вернётся
   case m2c::kfntest_ret_trap: goto fntest_ret_trap;
   ```
   Драйвер перед вызовом кладёт `PUSH(kfntest_ret_trap_eip)` в стек state →
   финальный RETN функции приводит в ловушку → группа возвращается →
   управление у драйвера. Минимально инвазивно, не влияет на игру.

## 4. Дизайн

**Драйвер** (расширение существующего v2_fn_test.cpp, режим `--fn-selftest` в
headless-бинаре или отдельная цель):
1. Static Initializer уже отработал (до main). Мини-сетап: стек/ss/sp как в
   m2c::init; тестовый DS = выделенная зона в m2c::m (сегмент вне занятых);
   myDrawInfo calloc — только для рендер-класса.
2. На каждый кейс: сгенерировать DS-образ + регистры → memcpy в тестовый DS →
   подготовить _STATE (ds/ss/sp/регистры, PUSH trap) → вызвать
   `sub_XXXXX(0,&st)` → снять DS-выход (эталон).
3. Тот же вход → `v2_fntest_call_*` на scratch-shadow (механизм Phase 0,
   готов) → побайтовый дифф с существующей skip-таблицей.
4. Репорт в формате FNTEST-DIFF/FAIL/SUMMARY + ненулевой exit-code.

**Генераторы входов** (иерархия, всё детерминировано фиксированным seed):
- ветко-направленные: по одному входу на каждую ветку asm (я извлекаю ветки
  при переписке — это и есть line-by-line анализ, работа уже делается);
- граничные: 0, ±1, 0x7FFF/0x8000 (знак), 0xFFFF (wrap), &0xFFF0±1 (тайлы);
- exhaustive: полный перебор ключевых 16-бит параметров (65536 → мгновенно);
- fuzz: PRNG-заполнение читаемых DS-полей, N тысяч кейсов.

**Контракт функции в реестре** (расширение реестра Phase 0): читаемые поля
(для генератора), писаемые поля (для фокуса диффа; дифф всё равно полный
64KB — ловит и записи «мимо контракта»), ключевые параметры-регистры.

**Самопроверка оракула**: инфраструктура Mode A (уже в дереве) — на реплейных
вызовах изолированный orig-вызов обязан дать тот же выход, что живой. Один
прогон при вводе драйвера в строй подтверждает корректность изоляции
(стек/сегменты/state настроены верно).

## 5. Применимость по классам функций

| Класс | Изолируемость | Вход | Примечание |
|---|---|---|---|
| A: DS-вычисления (collision/scroll/camera) | полная | DS-поля + регистры | идеал; с них начинать |
| B: VM-опкоды | полная | DS + объектный слот + **синтетический байткод в тест-es** | самый ценный (правило «VM 100% EXACT»); опкод = узкий контракт |
| C: рендер | полная | DS + синтетические тайлы/спрайты в fs/gs | дифф drawBuffer↔v2_render_buf существующим маппером; myDrawInfo уже отвязан от потоков (#179) |
| D: декомпрессия | полная | чанки из DATA.DAT, читаемого драйвером как файл | игра не нужна — только данные |
| E: интеграция (фазы, порядок, потоки, звук) | нет | — | остаётся за headless replay (редкие батч-прогоны; уже автономны) |

## 6. Автономный рабочий цикл (юзер не нужен нигде)

1. Читаю asm функции → контракт (поля/ветки/параметры).
2. Пишу/правлю v2 (line-by-line, как всегда).
3. Регистрирую в реестре (адаптер + контракт) — один раз.
4. `make` (инкрементально) + `./vikings_headless --fn-selftest=sub_XXXXX` —
   секунды: все ветки × границы × exhaustive × fuzz, обе реализации, дифф.
5. Расхождение → точный вход-репродьюсер (seed+параметры печатаются) →
   чиню → шаг 4. Repro-вход можно захардкодить в регресс-лист функции.
6. Изредка, батчем: headless replay корпуса (интеграционная страховка).

## 7. Ограничения и риски — честно

1. **Изоляция ≠ интеграция**: порядок вызовов, фазовая синхронизация, потоки,
   AIL — не проверяются; это остаётся за replay (E-класс). Synthetic-diff —
   инструмент ФУНКЦИОНАЛЬНОЙ эквивалентности, не системной.
2. **Trap-механика** (§3.5) — единственный непроверенный узел; проверяется
   экспериментом S0 (полдня). Fallback, если группа сопротивляется:
   pre/post-хуки Phase 0 уже стоят ВНУТРИ функций — драйвер может входить
   через wrapper и завершаться в post-хуке через longjmp (грубее, но работает).
3. **Оракул = m2c, не DOS** — тот же caveat, что у всей верификации проекта
   (M2C_PORT_DIFFERENCES.md); DOSBox-tier остаётся отдельной темой.
4. **Функции с не-DS входами** (v2_input_snapshot, spec-snap, глобалы) —
   контракт реестра обязан их перечислить; драйвер задаёт значения. Забытый
   глобал ловится недетерминизмом кейса (двойной прогон при --self-check).
5. **Функции, зависящие от alloc-адресов в DS** (сегментные поля 0x2E5C+) —
   драйвер прописывает свои тестовые сегменты в эти поля; для класса A
   нерелевантно.
6. **Стоимость на функцию**: адаптер + контракт (десятки минут при переписке,
   которая и так требует полного анализа функции). Генераторная библиотека —
   разовая.

## 8. Отношение к существующему

- Phase 0 (Mode A хуки) остаётся: (а) самопроверка оракула, (б) готовый
  v2-вызывной механизм и дифф; script-часть переиспользуется целиком.
- Рантайм-фикстуры (Mode B) остаются отложенными — решение юзера в силе;
  synthetic-diff их не воскрешает, у него другой источник входов.
- Лок-степ verify + replays — интеграционный контур, без изменений.
- REWRITE_STRATEGY.md: synthetic-diff усиливает фазу A (паритет) и остаётся
  верификатором после отрезания orig-слоя ТОЛЬКО если orig-объектники
  продолжают линковаться в тест-бинарь (orig умирает в игровом бинаре, но
  живёт в тестовом как оракул) — это снимает прежнюю зависимость «фикстуры =
  единственное наследие оригинала».

## 9. План

- **S0 (эксперимент, критерий go/no-go):** trap-механика + изолированный вызов
  `sub_15972`; кросс-чек изоляции против Mode A на attract; затем 3 ветки ×
  границы × exhaustive-65536-ax × fuzz — ожидание: 0 диффов; порча — ловится.
- **S1:** генераторная библиотека (ветки/границы/exhaustive/fuzz, seed) +
  контракт-поле в реестре; 2-3 функции коллизионного кластера
  (sub_1584e, sub_15da8, sub_13d68).
- **S2:** класс A целиком (~15 функций) + `--fn-selftest` в CI (быстрый шаг,
  без DATA.DAT — синтетике он не нужен, кроме класса D).
- **S3:** VM-опкоды на синтетическом байткоде (цель: каждый опкод = свой
  selftest; сверка перечня с B5-coverage).
- **S4:** рендер-класс с буферным диффом; класс D на DATA.DAT.
