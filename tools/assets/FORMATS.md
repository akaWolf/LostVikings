# Форматы ресурсов DATA.DAT (верифицировано по v2-рендеру, не по докам)

## Тайл — 64 байта, 8×8, byte=pixel (Mode X)
Источник: v2_render_funcs.cpp v2_draw_tile (зеркало sub_1689e).
```
pixel(x, y) = tile[(x & 3) * 16 + y * 2 + (x >> 2)]    x, y ∈ 0..7
```
- 4 «плана» по 16 байт; план p хранит столбцы x=p и x=p+4.
- Значение байта = индекс цвета в палитре (НЕ битплан).
- Тайлсеты: чанк = плотный массив таких 64Б-тайлов; tilemap-слово:
  bits 15..6 = offset тайла (кратен 64), bit 4 = hflip, bit 5 = vflip.

## Спрайт — полосы (mask + 8 data)/план
Источник: v2_render_funcs.cpp v2_draw_sprites (зеркала seg003 0x648/0x0B82).
- Type 0 (8×8, 72 байта): 4 плана × 2 полосы × (1 mask + 8 data).
  Полоса → 4 ряда × 2 байта: data[0,1]→row+0 … data[6,7]→row+3;
  mask-биты 76→row0, 54→row1, 32→row2, 10→row3 (бит=писать байт).
- Types 1-7 (16×16, 288 байт): 4 плана × 8 полос × (1+8).
  Полоса → 2 ряда × 4 байта: data[0..3]→row+0, data[4..7]→row+1;
  mask 7654→row0, 3210→row1.
- Общий случай (variable): size = 4 * strip_count * 9 (strip_count из
  объектной колонки OBJ_STRIP_COUNT).
- Байт данных = индекс цвета; маска управляет ЗАПИСЬЮ байта (цвет 0
  пишется, если бит маски стоит — это НЕ colorkey).

## Палитра — 768 байт
256 × RGB, 6-битные компоненты (0..63). DAC-порядок R,G,B.

## Экраны (raw-чанки через sub_10cd8)
plane_size (u16) + план-данные ×4 (по plane_size байт на план);
раскладка как у тайлов на уровне планов: столбец x идёт в план x&3,
внутри плана линейно по (y*width/4 + x/4). Ширина 320 (или 344 для
титула 17C — проверить по python/-наработкам при конвертации).

## LZSS-контейнер
[u16 decomp_size][поток LZSS] — extract_datadat.py делает byte-perfect
раундтрип на сыром уровне (535/535). Декомпрессор выдаёт size+1 байт
(канон: стоп по underflow ПОСЛЕ записи) — хвостовой байт хранить.

## Канон конвертеров (5.1)
extract(dec.bin) → assets/… → compile(assets) == dec.bin байт-в-байт.
Судья встроен в tools/assets/assetc.py (FAIL = конвертер не приземляется).
