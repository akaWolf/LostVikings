# Дифференциальные тесты функций orig ↔ v2 — глубокий анализ

Цель: тесты «на оригинальные функции игры», которые запускаются и на переписанных
C++ (v2) функциях. Т.е. один тест-кейс = один вход; эталон поведения снимается с
оригинала (m2c-порт `vikings.exe_seg000.cpp`), проверяемый — v2-реализация
(`src/sdl/v2_vm.cpp` и render-функции). Никаких synthetic-эталонов, придуманных
руками — только реальное поведение оригинала (правило «no guessing»).

---

## 1. Что уже есть и почему этого недостаточно

| Инструмент | Уровень | Ограничение |
|---|---|---|
| HEADLESS replay + phase barriers | вся игра, кадр | найдёт «на кадре N что-то разошлось», но не «какая функция неверна при данном входе»; полный прогон = минуты |
| PSNAP (10 фаз + per-sub-function MAIN_AFTER_*) | под-функции главного цикла | сравнивает НАКОПЛЕННОЕ shadow-состояние v2-зеркала, а не изолированный вызов; покрывает только захардкоженные точки главного цикла |
| trace_compare / coll_trace_compare | VM-опкоды | тоже накопленное состояние, только в живом барьерном прогоне |
| `src/rendering/test_seg003.c` | функция | synthetic-входы, тестирует отдельную ручную реимплементацию, НЕ v2 и НЕ сравнивает с orig |
| B5 opcode coverage | статистика | показывает ЧТО исполнялось, но не проверяет корректность |

Главный пробел: **нет изолированного, быстрого, повторяемого теста уровня
«функция(вход) → выход»**. Каждый баг v2 сейчас требует полного replay-прогона.
Второй пробел: перезапись replay'ев (как intro.inp на этой неделе) теряет
покрытие конкретных багровых состояний (#175 f2622, #177 f1125) — их нечем
запинить.

## 2. Ключевой принцип: golden-фикстуры из реального прогона

Тест-кейс («фикстура») = снимок реального вызова функции внутри
детерминированного headless-replay:

```
fixture = {
  meta:    { fn, source(replay,frame,call_idx), regs_in, regs_out },
  ds_in:   64KB DS до вызова orig-функции,
  ds_out:  DS после вызова orig (эталон; хранится как diff от ds_in),
  aux:     затронутые сегменты (es/fs/gs контент) до/после — по списку из реестра,
  globals: не-DS входы функции (v2_input_snapshot, sdl_spec_snap...) — по списку,
  bufs:    (для render-класса) хэш/дамп области drawBuffer после вызова
}
```

Прогон теста: `ds_in → v2_функция → diff(shadow, ds_out)` с существующей
таблицей исключений (`v2_ds_skip_ranges`: DosMemAlloc-адреса, AIL handles).
**Оригинал в раннере повторно НЕ вызывается** — его выход снят в живом прогоне,
где он и так исполнился. Это снимает 90% сложности харнесса (не нужно
реконструировать ss:sp/стек/глобалы для повторного orig-вызова).

Отличие от текущего барьерного verify — принципиальное: v2 получает **чистый
вход, равный входу orig**, а не своё накопленное shadow-состояние. Диф
локализует баг в самой функции, а не в дрейфе, накопленном за 2000 кадров.

## 3. Два режима исполнения (один реестр, одна логика сравнения)

**Mode A — inline differential (в живом прогоне).** Хук в seg000 вокруг вызова
функции F: снять ds_in → orig исполняется как обычно → снять ds_out → тут же
вызвать v2-адаптер на копии ds_in → diff. Не требует сериализации вообще
(aux-сегменты живые, в процессе). Включается env `FNTEST=sub_15972,...` в
обычном headless-прогоне scenarios. Стоимость: время replay (уже платим в CI).

**Mode B — offline fixtures (миллисекунды).** Тот же хук с env
`FNCAP=sub_15972:50` пишет фикстуры на диск (piggyback на CI-прогоне scenarios —
ноль лишнего wall-time). Раннер `vikings_fntest --run sub_15972` загружает
фикстуры, зовёт **только v2**, диффит. Итерация при отладке одной функции:
правка v2 → пересборка → <1 сек на 50 кейсов вместо минут replay.

Хранение: primary — «фикстура = рецепт» (regen из replay при изменении капчур-
точек; в репо не лежит, живёт в build-каталоге CI). Secondary — **pinned
fixtures** в репо для критичных багровых состояний (RLE-сжатый ds_in ~единицы
KB на кейс из-за разреженности DS): состояние #175/#177 сохраняется навсегда,
даже когда replay перезаписан. Это прямой ответ на боль этой недели.

## 4. Механика — подтверждено чтением кода

### 4.1 Оригинал (m2c)
- Каждая orig-функция **уже вызываемая по имени**: `src/vikings.exe.cpp:301`
  `bool sub_12352(m2c::_offsets, m2c::_STATE*){return _group1(m2c::ksub_12352,_state);}`
  — тонкие wrapper'ы на групповые диспетчеры (`_group1..3`, goto-метки,
  `case m2c::ksub_XXXX: goto sub_XXXX` — seg000:18466).
- Регистры — поля `m2c::_STATE` (src/aux/asm.h:148-181: eax..eip, cs/ds/es/fs/gs/ss,
  флаги CF..TF), память — глобальная `m2c::m`, `raddr(s,o)` (asm.h:705).
  Снять regs_in/regs_out = memcpy одного структа.
- Прецедент вызова orig-кода из внешнего C++: `redraw_tilemap(m2c::_STATE*)`
  (seg000:127) зовётся из render.cpp. Для Mode A/B повторный вызов orig не
  нужен; прямой вызов wrapper'ов остаётся опцией для будущих synthetic-тестов
  (Phase 4), феасибилити есть, но потребует подготовки ss:sp и проверки выхода
  из группы (ShadowStack, asm.h:200).
- Хук-точки в seg000 — тот же паттерн, что существующие
  `v2_record_orig_phase_snap` / `enter_trace_sub12352` вставки.

### 4.2 v2
- `v2_vm_shadow_ds` — статический массив (v2_vm.cpp:639). Тест: memcpy ds_in →
  shadow, выставить `v2_current_ds_val`/`v2_m2c_base`/shadow-сегменты, вызвать
  `v2_sub_XXXXX(shadow, args...)` напрямую — v2-функции синхронные, барьеры
  нужны только живому зеркалу, в тесте не участвуют.
- **Адаптер на функцию** (в реестре): маппинг regs_in → сигнатура v2
  (`ax→param`, `di→obj_idx`...). Пишется при добавлении функции в реестр —
  соответствует правилу «одна функция за раз, line-by-line».
- Полный снап DS уже практикуется: `v2_115d2_snapshot[0x10000]` (v2_vm.cpp:645),
  PSNAP full-DS снапы — код переиспользуется.

### 4.3 Сравнение
- DS-diff: существующий verify-компаратор + `v2_ds_skip_ranges` + вывод в
  формате `addr/orig/shadow` (как V2-DIVERGE) — узнаваемый формат.
- Render-diff: существующий маппер orig drawBuffer (planar
  `plane4_to_linear`) ↔ `v2_render_buf` (линейный 344×240) из
  `v2_verify_render_buf` — переиспользовать區域-сравнение viewport'а.
- Сегмент-diff: v2 shadow-сегменты vs orig es/fs/gs контент; alloc-адреса
  ремапятся через `v2_record_alloc`/`v2_get_alloc_size_para` (уже есть, GS MCB
  урок учтён).

## 5. Классификация функций по тестируемости

**A. Чистые DS-вычисления** — идеальный класс, DS-diff:
sub_15972, sub_1584e, sub_15da8, sub_13d68/13dd6/13e15, sub_13c0c (collision/
snap), sub_1064b (camera), sub_10704/10753 (scroll), sub_101be (palette DEC),
sub_105cb (exit-check: + regs_out CF), object-field хелперы. История багов
именно здесь (#175, #177, op_33, Y-drift) — максимальный ROI.

**B. VM-пассы** — DS-diff + es-aux, три гранулярности по нарастающей:
1) весь `sub_14207` за кадр (вход = DS+все объекты);
2) per-object exec (хук на внутреннем цикле);
3) per-opcode (хук на dispatch, парный к `v2_trace_object`).
Правило «VM 100% EXACT» получает автоматическую проверку: B5-coverage
показывает исполненные опкоды → цель: фикстура на каждый.

**C. Рендер в буфер** — buffer-diff + DS-diff (dirty-флаги пишутся в DS):
sub_1689e (тайлы), sub_1DD9C (спрайты), sub_1e16d (глифы), sub_1183d/HUD-цепочка,
sub_1DE05. Эталон = drawBuffer-область после orig-вызова.

**D. Декомпрессия / загрузка** — сегмент-diff:
loc_134dc (sprite decomp), sub_11204 (chunk), куски level-load цепочки
(sub_1774f...). Вход = сжатый источник + DS, выход = сегмент-контент.

**E. Вне охвата fn-тестов** (покрыто другим):
- AIL/SDL звуковые side-effects → audit-инфра B2 + audio pools (DS-bookkeeping
  этих функций тестируем, сам звук — нет);
- блокирующие циклы целиком (их итерация — это A/C-функции: v2_pw_iter_body и
  т.п. тестируются как обычные);
- DOS I/O / INT-обвязка / DosMemAlloc — фиксируются init'ом и alloc-таблицей.

## 6. Реестр (единственная точка добавления функции)

```cpp
struct FnTest {
  const char* name;              // "sub_15972"
  int capture_site;              // id хука в seg000
  void (*v2_adapter)(uint8_t* shadow, const m2c::_STATE& regs_in);
  const SegSpec* aux_segments;   // какие es/fs/gs сегменты входят в фикстуру
  const GlobSpec* globals;       // не-DS входы (v2_input_snapshot и т.п.)
  BufCompare buf_compare;        // NONE | VIEWPORT | RANGE
  const SkipRange* extra_skips;  // документированные девиации (напр. 1-frame SFX lag #126)
};
```

Добавление функции в тесты = 1 строка реестра + 1 адаптер + 2 строки хука в
seg000 (`FNTEST_PRE(id)/FNTEST_POST(id)`). Каждая — по процессу: сначала
line-by-line verify (как всегда), потом фикстуры закрепляют результат навсегда.

## 7. Билд и CI

- Харнесс = флаг `--fn-test` у **headless**-билда (init уже строит m2c::m,
  PSP/alloc, DATA.DAT, детерминизм #178/#179/#180 решён). Отдельного init-пути
  НЕ создаём. Mode B-раннер после init сразу уходит в фикстуры (кадры игры не
  гоняются).
- Makefile: цель `fntest` = headless-билд (тот же бинарь), плюс запуск.
- CI (build.yml, после Scenario replays):
  1) scenarios-прогон уже идёт → добавить env `FNCAP=...` → фикстуры падают в
     build-артефакты бесплатно;
  2) `./vikings_headless --fn-test=build/fixtures --all` — миллисекунды;
  3) pinned-фикстуры из `tests/fixtures/pinned/` — гоняются всегда.
- Локальный цикл: `make fntest && ./vikings_headless --fn-test --run sub_15972`.

## 8. Tier 3 (опционально, максимальная строгость): DOSBox ground truth

Всё выше сверяет v2 с **m2c-портом**. Но `M2C_PORT_DIFFERENCES.md` фиксирует,
что порт сам может отличаться от DOS-оригинала. Формат фикстур делаем
source-агностичным (`meta.source = m2c-replay | dosbox`): скриптованный
DOSBox-X debugger (breakpoint на входе/выходе функции по адресу, дамп DS/regs)
даёт фикстуры с НАСТОЯЩЕГО оригинала. Один и тот же раннер тогда проверяет:
- v2 против m2c (ловит баги v2),
- m2c против DOS (ловит баги порта — прямым вызовом wrapper'ов, Phase 4),
- v2 против DOS (итоговая истина).
Дорого (скриптинг DOSBox), поэтому — отдельный tier после обкатки Phase 1-2.

## 9. План внедрения

- **Phase 0 (proof, ~1 функция):** хук-макросы FNTEST_PRE/POST, реестр на
  sub_15972, Mode A на attract.inp. Критерий: 0 диффов на всех вызовах прогона;
  затем намеренная порча одной строки v2 → тест ловит.
- **Phase 1:** Mode B (сериализация RLE + раннер + `--run/--all/--list`),
  pinned-фикстуры для #175/#177 состояний (снять с текущих replay, пока они
  живы). CI-интеграция.
- **Phase 2:** класс A целиком (collision/scroll/camera ~15 функций) +
  sub_14207 гранулярность 1 и 2. Класс C (тайлы/спрайты/глифы/HUD) с
  buffer-diff.
- **Phase 3:** per-opcode (гранулярность 3) + цель «фикстура на каждый
  исполняемый опкод» (сверка с B5-отчётом), класс D.
- **Phase 4 (опц.):** прямой вызов orig-wrapper'ов для synthetic-краёв
  (границы карт, переполнения) + DOSBox tier.

## 10. Риски / ограничения (честно)

1. **Повторный вызов orig в раннере не делается** — эталон только из живого
   прогона. Synthetic-тесты (произвольные входы) поэтому в Phase 4, не раньше.
2. **Функции с не-DS входами** (input snapshot, spec-snap, SDL-время) требуют
   явного globals-списка в реестре; забытый глобал = недетерминизм фикстуры —
   ловится сразу (повторный прогон Mode B даст другой результат; раннер гоняет
   каждый кейс дважды при `--self-check`).
3. **Документированные девиации v2** (1-frame SFX lag #126, muted slot) —
   кодируются в extra_skips реестра со ссылкой на память/таск, НЕ глобальным
   исключением (правило «no verify exclusions» сохраняется: skip локален для
   конкретной функции и задокументирован).
4. **Aux-сегменты**: забытый сегмент в SegSpec → v2 читает мусор соседнего
   уровня в Mode B (в Mode A всё живое — расхождение Mode A/Mode B результатов
   само указывает на недоописанный SegSpec).
5. **Размер pinned-фикстур**: RLE по разреженному DS — единицы KB; лимит в
   репо, скажем, 100 кейсов; остальное — regen-from-replay.
6. Функции, чьи v2-зеркала намеренно работают в другой момент времени
   (blocking-loop entry/render порядок), тестируются на гранулярности их
   leaf-итераций, не целиком.

## 11. Отвергнутые альтернативы

- **Synthetic-first (как test_seg003.c):** ручные входы = придуманные состояния
  DS → риск нереалистичных/невозможных состояний и ложной уверенности;
  нарушает дух «no guessing». Годится только как дополнение (Phase 4) поверх
  реальных фикстур.
- **Выделение orig-функций в отдельную библиотеку:** m2c-код — связный
  goto/label-монолит с общим состоянием; экстракция = рискованный рефакторинг
  «PLEASE DO NOT MODIFY»-файла ради нуля выгоды (оба мира уже линкуются в один
  бинарь).
- **Только DOSBox-эталоны:** максимальная истина, но высокая цена входа;
  m2c-replay фикстуры дают 95% ценности бесплатно (инфраструктура уже есть),
  DOSBox — аддитивный tier, не фундамент.
- **Расширять барьерный PSNAP вместо изолированных вызовов:** PSNAP сравнивает
  накопленное состояние зеркала — не отвечает на вопрос «верна ли функция при
  данном входе» и не даёт офлайн-скорости.
