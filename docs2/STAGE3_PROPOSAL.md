# Stage 3 — транспилят .lvs → код: предложение архитектуры

Статус: STAGE 3 ЗАВЕРШЁН (коммиты 6e990e1..10ce7ca).
- Обе VM (объектная + anim) транспилированы для всех шести чанков;
  контроль потока доверяет ТОЛЬКО vm.pc (re-dispatch после каждого
  хендлера) — статические goto-рёбра ложны для динамических
  переходов (2D/36 через DS_SEARCH_JUMP).
- Верификация: канон 58/58 c пооп-кодным паритетом против real;
  авто-соак (37 монки-реплеев по паролям всех уровней) 37/37;
  V2_ONLY сверен вне документированного AIL-wall-clock класса.
  Побочно найдены и закрыты два до-существующих бага (#94 op_34
  stale-3CA, #95 walker op_14 P+3) — транспилят окупился как
  верификатор немедленно.
- GENCODE — дефолт всех сборок (NOGENCODE=1 — компайл-опт-аут,
  V2_GENCODE=0 — рантайм A/B). Канонические бинари пересобраны.
- Судьба интерпретатор-петли (решение юзера): остаётся unknown-pc
  fallback-ом + fn-test-хостом до конца B; физический выпил петли,
  216-таблицы и unknown-pc=FATAL — задача #96 (вместе с
  retirement-ом хендлеров B-инлайном). Факты для неё: fallback-хиты
  = 0 на 95 ранах; 164/216 опкодов статически живы, 52 — нет.
Дальше — B-пассы: инлайн семантики хендлеров в ген-код.

## Что есть на входе (итог Stage 1-2)

- Полная модель байткода: 54.9K инструкций, 100% операндов с
  верифицированной семантикой (expr-слой), state-разрез (~9K состояний,
  yield/exit/goto-терминаторы), владение шаблонами.
- Компилятор в обе стороны: identity байт-в-байт + авторинг-конвейер
  (lvsc → DATA.DAT → живой геймплей, доказано).
- Построчно верифицированные носители семантики каждого опкода:
  `v2_vm_op_*` хендлеры в v2_vm.cpp.
- Канал верификации: POSTVM DS-хэш каждый кадр + golden end-state
  (52+ реплеев канона).

## Вариант A (предлагаю): C++-генерация поверх существующих хендлеров

Генератор (python, из .lvs-модели) эмитит по одному C++-модулю на
чанк: каждое состояние = блок кода, инструкция = вызов ТОГО ЖЕ
хендлера, но с константными операндами, инлайненными из .lvs:

```cpp
// state S_1517 (template t3A)
case 0x1517:
    v2_acc = 0;                            // 51 0000
    if (v2_acc == obj.spawn_pool()) goto S_1527;  // 73 16 T1527
    v2_acc = obj.spawn_pool();             // 52 16
    obj.res_handle(v2_acc);                // 56 0a
    ...
```

Ключевые решения:
- **PC-таблица совместимости**: yield/call сохраняют в DS ОРИГИНАЛЬНЫЕ
  PC-числа (state-ID ↔ PC маппинг из .lvs). DS остаётся бит-в-бит
  совместимым с VM — dual-run сравним по существующему хэш-каналу,
  сейвы/anim-path (flags&0x200 перечитывает запись P) работают без
  изменений.
- **Диспетчер умирает**: вместо fetch-decode цикла — switch по
  сохранённому PC только на входе в тик (yield-резюме), внутри тика —
  прямые переходы (goto). Канальные операнды: выбор канала статичен
  (mode-байт — константа потока), значения по-прежнему из DS.
- **Хендлеры живут**: вся сложная семантика (коллизии, спавн, поиск,
  каналы, anim-VM) остаётся в верифицированных функциях v2_vm.cpp —
  транспилят генерирует только поток управления и константные операнды.
  Это минимизирует новый непроверенный код.
- **Anim-VM**: тем же способом (27 команд, отдельный генератор), но
  позже объектного кода — сперва доказываем объектный слой.
- **Dual-run**: build-режим V2_GENCODE: оба исполнителя живут в
  бинаре; на каждом тике объекта: исполнить VM-вариант на копии DS,
  ген-вариант на основной, сравнить (или наоборот) — грубее и проще:
  прогнать канон 52 реплеев на ген-бинаре и сравнить POSTVM-хэши
  против VM-бинаря (два прогона, без пер-тиковой синхронизации).
- **Недостижимый код**: генерится ВСЁ статически известное (54.9K);
  если рантайм просит PC вне таблицы (dead-код, добранный будущим
  dyn) — fallback на VM-интерпретатор с логом (гибридный период),
  затем регенерация.

Итог Варианта A: VM-цикл и таблица опкодов уходят; скрипты становятся
читаемым сгенерированным кодом; семантика остаётся в проверенных
хендлерах; DS-инварианты нетронуты → вся verify-инфраструктура
продолжает работать.

## Вариант B (отложить): полный HL-рантайм сразу

Генерация «настоящего» кода (структуры вместо DS-офсетов, никакого
acc, выражения слиты) — это красиво, но требует одновременно Stage 4
(GameState-носитель) и ломает бит-в-бит verify. Правильный порядок:
A → (Stage 4 переводит DS в структуры под НЕизменным ген-кодом через
view-слой) → упрощающие пассы над ген-кодом.

## Порядок работ (Вариант A)

1. Генератор объектного кода одного чанка (1C1) + PC-таблица.
2. V2_GENCODE-сборка: ген-исполнитель подключён параллельно VM.
3. Канон 52/52 на ген-бинаре = хэш-паритет с VM-бинарём.
4. Остальные 5 чанков; anim-VM генератор; выпил VM-диспетчера.

## Компоновка исполнителей по единицам трансляции (2026-09-06)

Двенадцать `.gen.inc` (54 МБ исходника) включались прямо в `v2_vm.cpp`. Под gcc -O2
такая единица не помещалась в память: раннеры GitHub (16 ГБ) теряли Windows-сборки
(mingw gcc), локальная сборка gcc была невозможна (clang собирал за ~1.2 ГБ).
Замеры (`ulimit -v 7 ГБ`, флаги CI `-O2 -g1`): VM без исполнителей — 0.43 ГБ / 12 с;
VM + `anim_01c1` — 1.46 ГБ; VM + `chunk_01c1` — «virtual memory exhausted» (одна функция
на 12 069 инструкций); VM + все chunk-исполнители, уже разбитые на куски, — тоже не
влезает (удерживаемый IR всей единицы).

Решение — две меры, семантика не тронута:

1. **Куски** (`tools/data/gen_transpile.py`, `GEN_PIECE = 512`): chunk-исполнитель эмитится
   как `static __attribute__((noinline)) bool v2_gen_exec_1cN_pK(V2VM&, int&)` по ≤512
   инструкций плюс маршрутизатор `v2_gen_exec_1cN`. Поток управления по-прежнему доверяет
   только `vm.pc`: инструкция заканчивается `continue` в switch своего куска; pc вне куска →
   `return false` маршрутизатору, тот входит в кусок-владелец диапазона
   (`[первый pc куска k, первый pc куска k+1)`); если владелец pc не знает — прежнее
   сообщение `V2-GEN-FALLBACK` и `return false`. `noinline` не даёт gcc склеить куски обратно
   (inliner «called once»). Тела инструкций (12 069 / 8 950 / 10 105 / 10 995 / 10 455 / 9 662
   блоков `L_xxxx`) сверены с прежними файлами — идентичны. Anim-исполнители не тронуты
   (одна функция на ~9.9k команд укладывается в ~1 ГБ).
2. **Отдельные TU** (`src/sdl/gen/exec_01cN.cpp`, по одной на чанк): включают
   `chunk_01cN.gen.inc` + `anim_01cN.gen.inc` и экспортируют `v2_gen_exec_1cN_entry` /
   `v2_gen_anim_1cN_entry`, которые зовут диспетчеры `v2_vm.cpp`. Общая часть —
   `src/sdl/v2_vm_gen.h`: `struct V2VM`, `V2AccProxy`, трейс-кольца, макросы
   `G_PRE/G_POST/V2_GEN_HASHSNAP/V2_GEN_TRACES` и объявления 207 функций `v2_vm.cpp`, которые
   зовёт сгенерированный код (`src/sdl/gen/v2_vm_gen_decls.gen.inc`,
   `tools/data/gen_vm_decls.py` — выводит список из самих `.gen.inc`, берёт сигнатуры из
   `v2_vm.cpp`, отказывается работать, если функция осталась `static`; `--check` для CI).
   У этих функций снят `static` — единственное изменение в их коде.

Память gcc после разбиения (тот же замер): `exec_01c1.cpp` — 3.85 ГБ / 7 мин 51 с (24 куска + anim_01c1), `v2_vm.cpp` —
0.43 ГБ / 12 с. Канон `tests/scenarios.sh` на HEADLESS-сборке с новой компоновкой: 58/58.

Ловушки регенерации:
- карта покрытия `_GS_COV` генератора не знала записей `FR(...)` (wave 14 перевела объектные
  колонки в `V2ObjRec[20]`), из-за чего регенерация теряла типизированные аксессоры
  `obj_*_at`; исправлено — `FR` покрывает как `FN` (регенерация всех шести chunk-файлов
  побайтно совпала с закоммиченными до внесения кусков);
- `lvs_full.anim_layer` подмешивает живой корпус `/tmp/animdump/*.txt`; без него
  `anim_01c2` (7770 → 7764 команд) и `anim_01c6` (7177 → 7175) регенерируются НЕ полностью —
  anim-файлы не регенерировать без корпуса (модель объявлена тотальной, пропуск = FATAL).
- `tools/data/gen_optable.py` парсил только `static void v2_vm_op_*` — теперь `static`
  необязателен (вывод не изменился; закоммиченный `optable_draft.json` и до того был
  устаревшим черновиком — не трогался).
