# Модель тайминга V2 (Stage 6.3, по фактам кода)

## Три слоя

### 1. Логический тик (канон геймплея)
- Генератор: сама vsync-wait-петля (`v2_vsync_wait_10130`) — на каждой
  итерации вызывает `v2_render_callback()` (зеркало ISR sub_1797b:
  DEC vsync_count @A39C + палитровый диспатч off_17974[303DE]).
- НЕ wall-clock: реплеи и голдены зависят только от СЧЁТА тиков; headless
  гоняет ту же петлю без пауз (CPU-скорость) с идентичным результатом
  (AA-IDENTICAL доказан на Stage 5).
- Игровой кадр = фазовая цепочка FRAME_BEGIN..FRAME_END c 3 page-flip
  ожиданиями → 3 тика ≈ 3×16мс ≈ канонические ~53мс DOS-каденции.
- Аудио: `v2_nopl_pump()` зовётся на итерации петли (INT8-модель:
  tick_hz/NOPL_FRAME_HZ тиков на вызов в frame-режиме).

### 2. Презентация (развязана)
- Отдельный тред (`render_thread_proc_v2`): события → снапшот
  drawBuffer→stableBuffer (`render_callback_v2`) → блит на экран
  (`updateDraw_v2`) → `v2_present_sleep()`.
- Показывает ПОСЛЕДНИЙ завершённый кадр со своей частотой; игровой темп
  на неё не влияет и наоборот.

### 3. Внешний бюджет главного цикла
- Ограничивает холостые обороты меню/ожиданий (`V2_FRAME_BUDGET_MS`);
  внутри игровых кадров доминируют wait-петли фаз.

## Единый источник темпа
`src/sdl/v2_timing.h`: V2_TICK_MS / V2_PRESENT_MS / V2_FRAME_BUDGET_MS,
`v2_tick_sleep()` (no-op в HEADLESS), `v2_present_sleep()`.
Диагностические ускорители: `V2_NOVSYNC=1` (без внешнего бюджета),
headless — без тик-пауз всегда.

## Интерполяция
Точка расширения `v2_interpolation_enabled()` — ВЫКЛ по умолчанию и не
реализована (roadmap 6.3: «опционально, off»). Реализация (когда
понадобится): презентер бленддит два последних stable-кадра по фазе тика.
