# Модель тайминга V2 (Stage 6.3, уточнена 2026-09-11 по DOSBox-стенду)

## Три слоя

### 1. Логический тик (канон геймплея)
- Генератор: сама vsync-wait-петля (`v2_vsync_wait_10130`) — на каждой
  итерации вызывает `v2_render_callback()` (зеркало ISR sub_1797b:
  DEC vsync_count @A39C + палитровый диспатч off_17974[303DE]).
- НЕ wall-clock: реплеи и голдены зависят только от СЧЁТА тиков; headless
  гоняет ту же петлю без пауз (CPU-скорость) с идентичным результатом
  (AA-IDENTICAL доказан на Stage 5).
- Игровой кадр = фазовая цепочка FRAME_BEGIN..FRAME_END c 3 page-flip
  ожиданиями → 3 тика = ТРИ ПОДКАДРА оригинала (render1/render2/render3), по
  одному обновлению 60 Гц Mode X на каждый. Камера и спрайты двигаются в
  каждом подкадре (объект шагает раз в тик, саб-спрайты догоняют его третями,
  вьюпорт скроллится каждое обновление) — это движение самого оригинала, не
  добавка порта (DOSBox-запись: 1–3 px на кадр 60 Гц).
- Аудио: `v2_nopl_pump()` зовётся на итерации петли (INT8-модель:
  tick_hz/NOPL_FRAME_HZ тиков на вызов в frame-режиме).

### 2. Темп тика = vsync дисплея (render_v2.cpp, 2026-09-11)
- Презентер после каждого `SDL_RenderPresent` (блокируется на vsync) выдаёт
  игре «vsync» по сетке 60 Гц на обновлениях дисплея: 60 Гц — каждое, 120 —
  каждое второе, 144 — чередование 2/3 (кратные 60 — точным делителем, прочие
  — измеренным отношением). `v2_tick_sleep()` → `v2_vsync_wait_game()`
  блокируется на нём; отставание не навёрстывается (в DOS опрашивается флаг
  ретрейса).
- Презентер защёлкивает новейший флип как можно позже перед следующим present
  (`v2_vsync_latch_sleep`, ~3 мс до обновления) → каждый подкадр показан ровно
  один раз, одно обновление задержки, как страничный флип VGA.
- Лок встаёт после прогрева (32 present-а, интервал должен устояться;
  стоп-интервалы длиннее 2.5 обновления — загрузка уровня — в среднее не
  входят). Без блокирующего present (V2_NO_PRESENT_VSYNC=1, dummy-драйвер,
  композитор без vsync) — собственный таймер 60.0 Гц с бегущим дедлайном
  (`V2_TICK_HZ`).
- PACING < VSYNC | VRR > (2026-09-11): VRR снимает vsync с рендерера, игра
  на таймере 60.0 Гц, презентер показывает каждый флип по сигналу
  `v2_flip_notify` — для G-Sync/FreeSync. STATS [ON] — оверлей с локом,
  интервалом present, подкадрами/кадр, DROPS/DOUBLES/LATE, FRAME/WORK,
  аудиобуфером и underrun-ами (`v2_stats.h`).
- Старая схема (`SDL_Delay(16)` ≈ 16.3 мс против 16.67 мс дисплея) била
  часами: раз в ~0.9 с подкадр удваивался, следующий пропадал.

### 3. Презентация
- Отдельный тред (`render_thread_proc_v2`): события → (при локе — ожидание
  до защёлкивания) → снапшот новейшего флипа (`render_callback_v2`) → блит
  (`updateDraw_v2` → present, который и задаёт темп) → без vsync
  `v2_present_sleep()` 15 мс.
- SMOOTH < NONE | AUTO | ON > (`v2_smooth.cpp`): интерполяция между двумя
  новейшими ФЛИПАМИ; AUTO — только на дисплее с частотой не кратной 60
  (75/90/144/165), где сетка 60 Гц неровная. См. RENDERING_SYSTEM.md.

### 4. Внешний бюджет главного цикла
- Ограничивает холостые обороты меню/ожиданий (`V2_FRAME_BUDGET_MS`);
  внутри игровых кадров доминируют wait-петли фаз.

## Единый источник темпа
`src/sdl/v2_timing.h`: V2_TICK_HZ / V2_PRESENT_MS / V2_FRAME_BUDGET_MS,
`v2_tick_sleep()` (no-op в HEADLESS; лок или таймер), `v2_present_sleep()`.
Диагностические ускорители: `V2_NOVSYNC=1` (без пауз вовсе), headless — без
тик-пауз всегда. Дампы: `V2_SMOOTH_DUMP=<dir>` → `flip_log.txt` (каждый флип с
временем) и `smooth_log.txt` (интерполированные кадры).
