# Система звука Lost Vikings — native AIL (актуально с #61/#79, 2026-08-06)

## Обзор

Оригинальная игра использует **AIL (Audio Interface Library, Miles)** с
драйвером **SBPFM.ADV** (Sound Blaster Pro FM): и музыка, и SFX — это
XMID-секвенции, проигрываемые FM-синтезом OPL3. В порте звуковой путь
ОДИН — **нативный**: оригинальный драйвер-блоб исполняется
8086-интерпретатором, его OPL-записи рендерит ядро Nuked OPL3, микс
уходит в SDL-устройство.

Legacy-канал (adlmidi-плеер + AudioPool, старая «decoupled mixer»
архитектура) удалён полностью (#79, коммит f62228a); от сабмодуля
`src/adlmidi` компилируется только `chips/nuked/nukedopl3.c`.

## Архитектура

```
game code (seg000 AIL-цепи: 17561 init / 176bd start / 177bb SFX /
           17912·1782a·1787f стопы / 108c8 mute / 178f1 fade)
  │  CALLF sub_1cXXX  (seg002-стабы: mov ax,fn; jmp sub_1bec2)
  ▼
seg002 sub_1bec2 — lookup (sub_1be8a) → dx:ax = far ptr хендлера В БЛОБЕ
  │  orig: push dx / push ax / retf  (= far-jump в блоб)
  ▼
loc_1bed6 МОСТ (#61): аргументы = 10 слов кадра [sp+4..] →
  v2_ail_orig_bridge(fn_off, args) → интерпретатор → ax/dx → RETF
  ▼
src/sdl/v2_ail_interp.cpp — 8086-интерпретатор .ADV-блоба
  два инстанса g_ails[2]: 0 = shadow (v2-мир), 1 = real (m2c-мир,
  плоская карта: параграф 0 → m2c-арена); recursive_mutex = модель
  PUSHF/CLI оригинала
  ▼
src/sdl/v2_native_opl.cpp — ОДИН Nuked OPL3 (модель DOSBox sbpro2):
  порты 0x220/1 = банк 0, 0x222/3 = банк 1 (reg|0x100), NEW-бит 0x105,
  4-op Connection Select 0x104 (тимбры SBPFM — четырёхоператорные!);
  mixer 0x224/5 — shadow-модель (игра программирует только Mic-пробу
  fn65, тома Master/FM не трогает); ×2 гейн к DOSBox-референсу
  ▼
src/sdl/play.cpp — SDL-устройство: sound_init открывает AUDIO_S16SYS,
  my_audio_callback = v2_nopl_mix + диагностики (SOUND-UNDERRUN /
  SOUND-CLIP / SOUND-CB-OVERRUN, NO_AUDIO_WORK, V2_AUDIO_DUMP-тап)
```

## Тикер (fn67)

- DOS: INT8 от PIT (частота из дескриптора драйвера).
- V2_ONLY: real-time по аудио-часам (потреблённые семплы устройства =
  стенное время) с cap догона: долг >64 тиков (~0.5 с) → сдвиг базы =
  честная ПАУЗА вместо пачечного отыгрыша; плюс pump внутри
  vsync-wait-петель (все блокирующие циклы игры проходят через них —
  ровно где DOS продолжал получать INT8). `V2_AIL_FRAME_TICKS=1` —
  детерминированный frame-режим для реплеев.
- default/verify: ВСЕГДА frame-accumulator (125/60 за pump), pump только
  из FRAME_BEGIN + blocking-tick — оба инстанса тикаются парой под одним
  локом → байт-идентичное состояние драйвера в обоих мирах; DS-verify
  сравнивает драйверные стейты как обычные байты DS.

## Ключевые механики драйвера (доказаны дизасмом блоба)

- fn64 desc / fn65 detect / fn66 init / fn97 register / fn9B→fn9C
  timbre-цикл / fnAA start / fnAB stop / fn98 deferred release /
  fnAE status / fnB1 fade (громкость → 0 за N мс; [state+0x2C] ← 0x64
  в момент вызова — старт рампы).
- Тимбр-кэш fn9C: слоты 0..191; каталог patch@0xB8B / bank@0xACB /
  busy@0xC4B / off@0x94B; LRU 0x64B/0x7CB; лимиты [0xD0F]=0xE00, [0xD11];
  тимбры 14 Б (2-op) / 25 Б (4-op); fn66→0x19BE сброс каталога и
  drum-map (REP STOSB 0xFF @0x12B9).
- Тик-арифметика 0x3382: [+0x30] += [+0x32], порог 0x64, tempo-slew
  [+0x32]→[+0x34].
- C0-хендлер 0x26C9: [12A9+ch]=prog → 0x15E9 → [1289+ch]=слот;
  fetch-гейт 0x351F по [2A2B]&0x80.

## DS-состояние звука (все адреса типизированы в v2_gamestate)

- Указатели стейтов @0x9920 → пять XMID-блоков по 0x208 @0x9950..0xA378.
- Handle-слоты `[si−0x66F4]` → 0x990C.. (si=0 музыка, 2..8 SFX);
  seq-слоты `[si−0x66EA]` → 0x9916..
- Music-диспетчер off_3285A (@0xA37A, 5 CS-адресов; индекс = snd_type
  [25B7], sub_17749).
- Track→chunk-id таблица @0xA384: sub_1775d читает
  `[track*2−0x5C7C]` (wrap), прибавляет [86B8] и грузит чанк трека в
  seg_sound через sub_10982.
- Конфиг карты: [86B6] (sound==8) / [86B8] (music==3) — из хвоста
  DATA.DAT.

## Юнит-мир (fn-test)

Гейт закрыт наглухо: `v2_fntest_running` → native off; на входах
sub_176bd / sub_177bb стоят fntest-RETN-леса (иначе глухой fn9B-стаб
эхоит 0x9B≠0xFFFF — вечный timbre-цикл на синтетическом DS; репро —
sub_154bf). Десять юнитов звуковой семьи — SKIPPED-PORT-NATIVE; покрытие
семьи = DS-паритет default-мира по всему интерпретируемому драйверу +
V2_ONLY-смок + 15-сценарный набор.

## Диагностика

- `V2_AIL_TRACE=1` — пошаговый трейс интерпретатора.
- `V2_OPL_TRACE=<f>` — поток «тик банк рег знач» (сравнение с DOSBox-DRO,
  методика — memory reference-dosbox-instrumentation).
- `V2_AUDIO_DUMP=<f>` — сырой s16le device-bound микс («что слышал юзер»).
- `NO_AUDIO_WORK=1` — колбэк отдаёт тишину (перф-изоляция).
- `tests/native_ail_check.sh` — V2_ONLY-смок: boot + music + SFX,
  faults=0, слот-кап, ≥1000 OPL-записей.

## Данные

- .ADV-блоб = чанк 0x1CC DATA.DAT (LZSS; size+1-канон — python/lv_lzss.py:
  underflow-выход, резать по dx==0 = потерять хвост).
- Банк тимбров — соседний чанк; валидация ресурса — magic «Copy»
  в байтах 2–5.
- XMID-треки уровней: chunk-id из таблицы @0xA384 (+[86B8]).

## Опция SC-55 (UX этап 11, 2026-09-09)

Третий режим `SOUND < PC | SNES | SC55 >` (`v2_options.sound_mode` 0/1/2, cfg `sound=`;
`snes_sound=1` старых конфигов читается как режим 1). Идея: XMIDI-партии игры — обычный
GM-MIDI (программы 0–126, каналы 1–10, ударные на 10), и та же музыка на Roland SC-55
звучала в 1992 «по-богатому»; вместо sound font'ов (решение юзера — звучат плохо) и
железа — эмулятор.

- Ядро: **Nuked-SC55** (`src/sdl/third_party/nuked_sc55`, GPL-2.0-or-later; H8/532 MCU,
  PCM-чип, суб-MCU; ROM-ы модуля не входят — юзер кладёт их в `roms/sc55/` (или
  `sc55_roms=<dir>` в cfg) под именами Nuked-SC55: mk2 — `rom1.bin rom2.bin waverom1.bin
  waverom2.bin rom_sm.bin`, mk1 — `sc55_rom1.bin sc55_rom2.bin sc55_waverom1..3.bin`, а также
  наборы cm300/jv880/scb55/sc155). Ядро собрано с `-DNUKED_SC55_EMBEDDED`: свои окно/LCD,
  аудио-устройство и MIDI-вход стандалона отрезаны (`lcd_stub.cpp` — LCD без окна), поверх
  ядра — C-API `nsc55_load(dir)` (автодетект набора по именам файлов, unscramble wave-ROM),
  `nsc55_start(ring)` (MCU_Init/PatchROM/Reset + рабочий поток эмуляции с темпом по указателю
  чтения), `nsc55_read(out, frames)` (кольцо семплов, нули при недоборе), `nsc55_post(byte)`
  (UART модуля), `nsc55_stop`.
- Дорожка MIDI (`v2_midi.{h,cpp}`): наблюдатель диспетчера 2629 драйвера — единственной
  точки, через которую драйвер выдаёт КАЖДОЕ канальное сообщение (ноты вкл/выкл, включая
  отложенные XMIDI-выключения `midi_2629(mch|0x80,…)`, контроллеры уже после масштабирования
  громкости драйвером, программы, питч). Тап стоит на ЗВУЧАЩЕМ экземпляре драйвера и только
  на нём: в V2_ONLY — вход нативного `v2_ailnat_midi_2629` (игровой поток; при
  `V2_AIL_NATIVE=0` — тап интерпретатора на экземпляре 0); в verify-сборке — тап
  интерпретатора на sink'е (#83: слышимый экземпляр — интерпретируемый блоб на аудио-потоке;
  проверка `ip == 2629` в `AilInterp::step`, аргументы из дальнего кадра `[sp+4]/[sp+6]/[sp+8]`
  = status/data1/data2 — 2629: `push bp / mov bp,sp / mov si,[bp+8] / mov di,[bp+6] /
  mov cl,[bp+0Ah]`), часы дампа — тики sink'а. Молчащая verify-пара тапа не получает.
  AIL-контроллеры 0x70/0x71/0x72 (protect/lock/bank) — не MIDI, в дорожку не идут. Дорожка —
  только презентация: ни DS, ни состояния драйвера не трогает; без опции и без дампа — пустой
  вызов. В headless-сборке аудио-потока нет — sink не строится, дамп там пуст (дамп снимать
  V2_ONLY-бинарём с `V2_AIL_FRAME_TICKS=1` или оконным verify-бинарём под dummy-аудио).
- Обвязка (`v2_sc55.{h,cpp}`): старт при режиме 2 — в V2_ONLY ещё в `v2_main` до игрового
  потока, иначе при первом тике `v2_ui_service` (загрузка ROM-ов один раз, `nsc55_start(8192)`
  — кольцо стандалона по умолчанию, 124 мс задержки); без ROM-ов — тост со статусом и возврат
  режима на PC. GS-reset при старте НЕ шлётся: модуль и так включается в GS-состоянии, а
  sysex во время загрузки SC-55mk2 останавливает его на ~5 с тишины (зонд 2026-09-10: с ним
  первая озвученная нота на 5.0 с, без него — с 0 мс).
  **Гейт загрузки.** Прошивка модуля озвучивает ноты не сразу (зонд: SC-55mk2 v1.01 — с
  0.08–0.17 с модульного времени, SC-55 v1.21 — с 2.0 с; ноты, посланные раньше, не звучат).
  Сигнал готовности — первое `LCD_Enable(1)` прошивки (`lcd_stub.cpp`: `nsc55_lcd_enabled`;
  mk2 — 0.29 с, mk1 — 2.18 с, обе позже первой озвученной ноты, т. е. консервативно). До
  готовности `v2_sc55_mix` кадры модуля ТЯНЕТ (эмуляция темпируется потребителем: рабочий
  поток стоит, пока читатель не сдвинется), но выбрасывает — в буфере остаётся OPL; события
  в UART не идут. Состояние каналов (bank CC0/32, program, контроллеры, pitch, pressure; CC121
  сбрасывает по RP-015; CC120/123 не состояние) ведётся ВСЕГДА (`v2_sc55_observe` из
  `v2_midi_event`, при любом режиме), и в момент готовности `v2_sc55_service` (игровой поток:
  из `v2_ui_service` каждый тик И на пути события `v2_sc55_midi` — первая музыка идёт из цепи
  инициализации до первого тика) выдаёт его в модуль (bank → program → CC → pitch → pressure),
  затем живые события. То же при включении опции посреди игры: модуль слышит текущие
  инструменты/громкости, звучащие ноты OPL теряются (неизбежно).
  `v2_sc55_midi` — статус + данные (2 байта для 0xC0/0xD0, иначе 3) в UART; единственный
  производитель UART — игровой поток. `v2_sc55_mix` (аудио-поток, после SNES-микса в
  `my_audio_callback`) — линейный ресемплинг 64000 (mk1/jv880) или 66207 (mk2) Гц → частота
  устройства, ЗАМЕНЯЕТ OPL-рендер в буфере (OPL по-прежнему считается — его DS-мир и канон не
  зависят от режима). Диагностика: `V2_SC55_TRACE=1` (события, кольцо, UART), зонд загрузки —
  scratchpad boottest (не в репо).
  Проверено 2026-09-10 (V2_ONLY, level1.inp, dummy video/audio, `V2_AUDIO_DUMP`): mk2 — модуль
  готов до первой музыки, титульная тема звучит с первой ноты на SC-55, уровень — без разрывов;
  CPU всего процесса ~60 % одного ядра; громкость сопоставима с OPL (RMS ~1500–2000 против
  ~1300–2000). Наборы на машине: `roms/sc55` = SC-55mk2 v1.01, `roms/sc55-mk1` = SC-55 v1.21
  (= дамп MAME `sc55`: rom2 CRC 2dc58549, внутренний ROM H8/532 CRC 4ed0d171).
- Проверка без ROM-ов: `V2_MIDI_DUMP=<f.mid>` — SMF type 0 всей партии, выданной драйвером
  (тик драйвера `v2_nopl_ticks_done` = тик MIDI, division = tick_hz, темп 1 000 000 мкс —
  четверть в секунду). Сравнение нот с `assets/music/<cid>.derived.mid` (конвертер
  `assetc.py xmid_to_midi`, 120 тиков/с): последовательность note-on трека уровня должна
  войти в дамп подряд.

## Опция MT-32 (UX этап 11, 2026-09-10)

Четвёртый режим `SOUND < PC | SNES | SC55 | MT32 >` (`sound_mode` 3). Не переадресация MIDI:
музыка игры написана под Roland MT-32 (драйверов GM в игре нет; каналы 2–10 = раскладка
MT-32; номера программ — карта MT-32; 64 пользовательских тембра в банке 020F), поэтому
воспроизводится **сам MT-32-мир игры**: её собственный драйвер MT32MPU.ADV (чанк 0x1CF)
исполняется вторым экземпляром AIL-интерпретатора на аудио-потоке (по образцу sink #83), а
байты его порта MPU-401 идут в эмулятор MT-32 (Munt / libmt32emu 2.8.3,
`src/sdl/third_party/mt32emu`, LGPL-2.1-or-later; ROM-ы модуля — юзера: `roms/mt32/`
(`MT32_CONTROL.ROM` + `MT32_PCM.ROM` либо CM-32L), или cfg `mt32_roms=<dir>`).

Что меняет конфигурация карты 8 в самой игре (seg000: загрузчик 2B11–2B39, sub_17561
7636–7672, sub_1775d 7782) и что воспроизводит экземпляр (`src/sdl/v2_mt32.cpp`):
- данные: драйвер 0x1C7+8 = 0x1CF; банк тембров 0x20C+3 = 0x20F (64 MT-32-тембра по 248 байт,
  банк 1, патчи 0–63); набор эффектов 0x207+3 = 0x20A (те же 98 секвенций в аранжировке
  MT-32); треки — вариант `table[track]+3` (у канона FM = +2: [86B8]=2). В экземпляре они лежат
  в своих параграфах (B000/C000/D000 — слоты FM-мира малы: FM-банк 6 КБ против 16 КБ), и
  указатели игры в вызовах переписываются (fn97 args[2], fn9C args[4]); подмена трека идёт
  через кольцо вызовов в порядке с ними (хук в `v2_music_load_1775d_helper`);
- вызовы: тот же поток вызовов, что получает звучащий драйвер (V2_ONLY — из `sh_call`,
  verify — из моста `v2_ail_orig_bridge` с переводом offset→код fn по таблице FM-блоба),
  с тем, что игра взяла бы у самого драйвера MT-32: fn66 — параметры таймера из ЕГО
  дескриптора (fn64), тик — [desc+0x14]+5 (125 Гц); fn99 — ЕГО размер кэша (0 → у MT-32-мира
  нет fn9A); fn9C FM-мира отбрасываются (обслуживание запросов тембров FM); хэндлы
  секвенций — номера слотов драйвера, отображение FM→MT32 по каждой регистрации
  (предзагрузка занимает слот 0);
- хвост init карты 8 (`preload`): чанк 0x215 в буфер трека, sub_176bd с [A378]=0 — fn97, затем
  каждый запрос тембра (fn9B) обслуживается из банка (реплика sub_17512: 6-байтовый индекс
  {patch, bank, off}) через fn9C — 64 тембра = 320 SysEx в область памяти тембров 08 xx
  (по 24+68… байт), — потом fnAA. Сама секвенция 0x215 — это lock канала (CC110) + program
  change 0..63 за 8.4 с (драйвер по каждому пишет запись patch memory 05 xx → тембр памяти) +
  unlock. Она идёт ФОНОМ; загрузка трека уровня перезаписывает её буфер (как и в DOS), и
  если уровень стартует раньше её конца, lock остаётся навсегда → канал 9 музыки молчит
  (в реальной игре её прикрывают логотипы/интро; реплей level1.inp срезает интро за 1 с —
  так и нашлась ошибка «предзагрузка при первой регистрации», исправлено: предзагрузка
  ровно в хвосте init, после fn99/fn9A);
- MPU-401 (UART): порты берутся из ячеек самого драйвера (fn65 пишет cs:43F = data, cs:441 =
  status/command); модель — ACK 0xFE на любую команду (FF reset, 3F UART), DRR всегда
  готов, DSR = есть ли ACK; запись в data = байт MIDI → `MidiStreamParser` Munt → `playMsg` /
  `playSysex` с меткой времени `getInternalRenderedSampleCount() + смещение в буфере`
  (pump в блоках по 256 кадров в `v2_nopl_mix`, рендер один раз за колбэк через
  `SampleRateConverter` GOOD на частоту устройства, ЗАМЕНЯЕТ OPL-рендер). Драйвер ещё читает
  BIOS 0040:0063 (база CRT) и ждёт бит 3 порта 3DA (задержки по обратному ходу луча) — в
  экземпляр отображена своя BDA с 03D4, бит переключается на каждом чтении; PIC 20/21/A0/A1 — тишина.
- проверка без ROM-ов: `V2_MT32_DUMP=<f.mid>` — SMF всего потока драйвера (в т. ч. SysEx),
  `V2_MT32_TRACE=1` — таблицы каналов драйвера (cs:40F slot / 41F bank / 42F patch), fn97/fn9B.
  2026-09-10, level1.inp 30 с: init → reset 7F, назначение партий 10 00 0D = 01..09, резерв
  партиалов 03 04 03 04…, реверб; предзагрузка 64 тембров; трек 01EC (MT-32-вариант уровня 1):
  все 7 каналов нота в ноту по порядку (57/334/123/82/60/67/485), ударные через CC58 → SysEx
  03 01 4x; CC59 = reverb switch патча, CC60 = bender range (записи 05 xx +6/+4); FM-вариант
  01EB с дампом не совпадает (другая аранжировка) — играет именно MT-32-набор.
